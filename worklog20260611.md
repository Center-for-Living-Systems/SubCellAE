# Work Log — 2026-06-11

**Project:** SubCellAE nonad-vs-ad screening classifier  
**Branch:** `exp/nonad-vs-ad-cls`  
**Goal:** Improve cross-dataset generalization of the vinc-trained binary FA classifier (adhesion vs. no-adhesion) when applied to ppax (pPaxillin) patches.

---

## Context

A binary EfficientNet classifier is trained on vinc (Paxillin ch1) labeled patches and evaluated on:
- **val**: held-out vinc patches (group-aware split, 20%)
- **ppax eval**: all labeled ppax patches, histogram-matched to vinc distribution

The key generalization metric is **ppax balanced accuracy** and especially **ppax NAD recall** — most models collapse to predicting everything as adhesion (rec_NAD = 0.00) on ppax.

Channel layout: ch0=marker (vinculin for vinc), ch1=paxillin.  
All training on vinc ch1 (paxillin) patches unless noted.

### 4. GammaJitter augmentation added

Added `GammaJitter` class to `subcellae/screening/dataset.py`:
- Applied after `IntensityJitter`, clips to [0,1] then applies `img ** gamma`
- `gamma ∈ [gamma_lo, gamma_hi]` sampled uniformly per patch
- Targets non-linear histogram shape variation (complements linear scale+shift of IntensityJitter)
- Wired into pipeline and config parser; new YAML key `gamma_jitter: {enabled, gamma_lo, gamma_hi}`

Tested two gamma ranges on top of jittercrop:
- Aggressive: gamma ∈ [0.4, 2.5]
- Mild: gamma ∈ [0.7, 1.5]

### 5. Threshold analysis (minimum false alarm)

Explored val-set threshold calibration under two framings:
- **Strategy A** (AD is signal): threshold maximising AD F1 on val → apply to ppax
- **Strategy B** (NAD is signal): threshold maximising NAD F1 on val → apply to ppax

Finding: the val-optimal threshold does not transfer to ppax. Default 0.5 already sits near the NAD F1 optimum on val. The bottleneck is score distribution shift between vinc and ppax, not threshold placement.

## Key Findings

1. **ppax NAD recall is the hard problem.** Most conditions predict every ppax patch as AD (rec_NAD = 0.00). The challenge is purely cross-dataset generalization, not in-distribution performance.

2. **Spatial jitter crop is the most effective intervention.** Adding ±4px translation + ±15° rotation from source frames (jittercrop) is the only augmentation that consistently recovers ppax NAD recall. Best result: **jittercrop b2 — ppax bAcc 0.686, NAD recall 0.40, NAD precision 0.86**.

3. **Intensity jitter alone does not help ppax generalization.** The `jitter` condition achieves the best val accuracy (0.919) but collapses on ppax (rec_NAD = 0.00 for b0).

4. **Multichannel (vinc ch0 + pax ch1) helps ppax AUC but not recall.** `jitter+mc b0` achieves the highest ppax AUC (0.957) but NAD recall is only 0.27 — the model discriminates well in score space but the threshold is in the wrong place.

5. **Adding multichannel to jittercrop hurts.** Static vinc ch0 samples dilute the spatial diversity signal from jittercrop; ppax bAcc drops from 0.686 → 0.572.

6. **Gamma jitter does not improve ppax generalization.** Both gamma ∈ [0.4, 2.5] and [0.7, 1.5] on top of jittercrop reduce ppax bAcc and NAD recall vs. plain jittercrop. Possible mechanism: gamma distorts the local texture features EfficientNet relies on for NAD detection.

7. **Histogram matching hurts CNNs, helps ViTs.** Training-time HM reduces ppax performance for EfficientNet/ResNet (NAD recall → 0). ViT-small ppax AUC improves +0.29 with HM. However, ViT-small + jittercrop + HM combined underperforms — likely too much noise for a 1,295-patch dataset.

8. **Threshold tuning on val does not transfer to ppax.** Score distributions shift between vinc and ppax; the val-optimal threshold does not generalise. Default 0.5 is already near-optimal for most models.
