## 1. EnlargedCropDataset (carried from 06-10)

**Problem**: JitterCropDataset applied scipy rotation per patch inside `__getitem__`, causing
two interpolation rounds (load-time + augment_contrastive_view) and slow DataLoader throughput.

**Solution**: New `EnlargedCropDataset` (kept JitterCropDataset for the nonad-vs-ad branch):

- Loads 58×58 context patches at init (size = 2·ceil(√2·(ps/2 + max_shift)) = 58 for ps=32, shift=4)
- Pre-pads all source frames at init (`np.pad(mode='reflect')`) so `__getitem__` is a zero-allocation numpy slice
- Returns `(1, 58, 58)` float32 tensor; NO rotation or jitter at load time
- Training loop applies `_jitter_rot_crop()` — batched GPU affine (affine_grid + grid_sample) — independently for view1 and view2

`_jitter_rot_crop(x, max_shift_px, max_angle_deg, out_size)`: builds a (B,2,3) theta matrix
(`cos·s, sin·s, tx`; `-sin·s, cos·s, ty`) from per-image random angles and shifts, then calls
`F.affine_grid` + `F.grid_sample` in one GPU pass. Single bilinear interpolation, no double-degradation.

## 2. Performance fixes

### 2a. np.pad bottleneck
**Problem**: First submit (jobs 934185/934186) ran 16+ minutes without printing a single epoch —
`np.pad(full_frame, pad, mode='reflect')` was inside `__getitem__`, called per patch per epoch.

**Fix**: Pre-pad at `__init__` into `self._frames_padded`. Applied to both `EnlargedCropDataset`
and `JitterCropDataset`.

### 2b. stdout buffering in SLURM
**Problem**: `print()` is fully buffered in non-TTY mode (~8 KB buffer); epoch loss lines
never appeared in the log file until the buffer filled.

**Fix**: Added `flush=True` to all epoch `print()` calls in `train_contrastive_ae` and
`train_supervised_contrastive_ae`.

## 4. Jobs 934303 / 934304 — enlcrop baseline (completed)

| Job | Model | Warmup | Result |
|-----|-------|--------|--------|
| 934303 | ConAE (NT-Xent) | 200 ep | recon stuck 0.0074→0.0073 throughout warmup; contrast overfits post-warmup |
| 934304 | SupCon | 0 (fix not yet applied) | recon 0.006→0.0046; max 0.67; best visual quality of all runs |

**Key finding**: ConAE warmup provided no benefit — pure MSE on sparse FA data converges
to a near-constant "mean output" minimum within the first few epochs. The contrastive loss
(SupCon with class labels) actually helps reconstruction by forcing the encoder to learn
FA-discriminative features, which the decoder can exploit.

**Reconstruction display**: Both runs show dark reconstructions because the model outputs
max ~0.33 (ConAE) or ~0.67 (SupCon) while input peaks at 1.2; all displayed at [0,1] scale.

### 4a. Best-checkpoint bug (fixed)

`min_epochs_for_best=200` caused tracking to start at epoch 200 — the last warmup epoch —
whose val loss (pure recon, ~0.008) permanently beat all post-warmup val losses (recon+contrast, ~2.1).
`model_best.pt` was always the last warmup epoch, before any contrastive training.

**Fix** (in both `train_contrastive_ae` and `train_supervised_contrastive_ae`):
```python
past_warmup = (epoch + 1) > warmup_epochs
if past_warmup and (epoch + 1) >= max(min_epochs_for_best, 1) and vl < best_val_loss:
    ...
```

## 6. sc2 experiment — input ÷2 + no Sigmoid

**Motivation**: Input FA pixels reach ~1.2, clipping against the Sigmoid output ceiling of 1.0.
Hypothesis: dividing input by 2 (→ [0, 0.6]) and removing Sigmoid would let the decoder
match the input amplitude directly.

**Code changes**:
- `EnlargedCropDataset`: added `input_divisor: float = 1.0`; applied as `region / input_divisor` in `__getitem__`
- `ContrastiveAE`: added `output_sigmoid: bool = True`; decoder conditionally appends `nn.Sigmoid()`
- `AEConfig`: added `enlarged_crop_input_divisor` and `output_sigmoid` fields
- `run_ae_from_config.py`: parses `enlarged_crop.input_divisor` and `model.output_sigmoid`
- New configs: `ae_contrastive_..._enlcrop_sc2.yaml`, `ae_supcon_..._enlcrop_sc2.yaml`
- New sbatch: `sbatch_conae_vinc_enlcrop_sc2.sh`, `sbatch_supcon_vinc_enlcrop_sc2.sh`

### 6a. Jobs 934342 / 934343 — sc2 with no Sigmoid (completed, failed)

| Job | Model | Result |
|-----|-------|--------|
| 934342 | ConAE sc2 | recon 0.0018 (= 0.0073/4 as expected), max 0.16 vs input 0.61 — same 26% ratio; no improvement |
| 934343 | SupCon sc2 | **complete collapse**: recon constant (min=max=mean=0.051), contrast stuck at 5.53 (random ceiling) |

**Root cause — mean collapse without Sigmoid**:

Without `nn.Sigmoid()`, the linear decoder converges to outputting the dataset mean constant
within the first few epochs. For sparse FA patches (mean ≈ 0.07), MSE is minimized at exactly
one constant value with zero spatial gradients. The decoder collapses before the encoder can
learn anything useful.

Sigmoid provides gradient friction: the logistic nonlinearity has a small but non-zero slope
near the constant-output equilibrium, slowing collapse and giving the contrastive objective
time to drive representation learning.

SupCon sc2 was worst because the 100-epoch warmup (pure recon) collapsed the encoder completely
before contrast was introduced.

### 6b. Fix: restore Sigmoid, set SupCon warmup=0

Updated both sc2 configs: `output_sigmoid: true`, SupCon `warmup_epochs: 0`.

**Rationale**: sc2 (÷2) still valid — input in [0, 0.6] fits inside Sigmoid's (0,1) range with
no clipping (pre-sigmoid value needed: logit(0.6) ≈ 0.43, easily achievable). Sigmoid prevents
collapse. No warmup follows the pattern of the best SupCon result (934304).
